# BrickBlast

마우스와 터치로 플레이하는 HTML Canvas 벽돌깨기 게임입니다. 별도 패키지 설치 없이 실행됩니다.

## 실행

`index.html`을 브라우저에서 직접 열어 플레이하세요. 

- 위쪽으로 드래그하고 놓으면 공이 연속 발사됩니다.
- 벽돌의 숫자는 남은 내구도이며, 초록색 +를 맞히면 다음 턴의 공이 늘어납니다.
- 스코어는 1부터 시작하고 다음 단계로 진행할 때마다 1씩 올라갑니다. 벽돌 타격·파괴에는 추가 점수가 없습니다.
- 공이 모두 돌아오면 벽돌이 한 칸 내려오고 새 줄이 추가됩니다.
- 벽돌이 바닥에 닿으면 게임이 종료됩니다.
- 빠른 회수 버튼으로 남은 발사를 끝낼 수 있습니다.
- 최고 점수는 브라우저의 로컬 저장소에 저장됩니다. 이전 타격 점수 기록과는 별도로 저장합니다.

## 코드 읽는 순서

- `index.html`: 점수판, 게임 Canvas, 종료 화면, 버튼의 구조입니다.
- `style.css`: 화면 배치와 색상입니다. 선택자마다 속성을 나누어 적었습니다.
- `constants.js`: 공 속도, 벽돌 크기, 발사 간격 등 고정 설정입니다. HTML에서 게임 코드보다 먼저 불러옵니다.
- `index.js`: 게임 로직입니다. 위에서부터 설정 참조와 상태, 턴 진행, 충돌 처리, 화면 그리기, 입력 처리 순서로 배치했습니다. Canvas 크기처럼 실행 시 읽는 값은 이 파일에서 계산합니다.

`index.js`를 처음 읽을 때는 다음 흐름부터 따라가면 됩니다.

1. `resetGame()`이 점수와 공 개수를 초기화하고 첫 벽돌 줄을 만듭니다.
2. 포인터 입력으로 `updateAim()`이 방향을 정하고, 손을 놓으면 `launchBalls()`가 발사를 시작합니다.
3. `animateFrame()`이 매 프레임 `updateShooting()`으로 공을 이동하고 `drawGame()`으로 화면을 그립니다.
4. 공이 모두 돌아오면 `finishTurn()`이 벽돌을 내리고 다음 단계 또는 게임 종료를 결정합니다.

`ballCount`는 이번 턴의 공 개수, `firedBallCount`는 이미 발사한 개수, `collectedBallCount`는 다음 턴에 추가할 개수입니다. `launchX`는 발사 위치이며, 첫 공이 돌아온 위치(`firstLandingX`)가 다음 턴의 발사 위치가 됩니다.

파일 상단의 `let` 변수는 여러 함수와 프레임이 함께 사용하는 게임 상태입니다. 예를 들어 `score`는 턴 종료 시 증가하고 화면 갱신 시 읽습니다. 함수 안에서 매번 새로 선언하면 이전 상태를 이어갈 수 없으므로 바깥 함수 범위에 두었습니다. 충돌 전 위치나 반복문 인덱스처럼 잠깐 쓰는 변수는 사용하는 함수 안에 둡니다.

충돌은 `moveBall()`에서 처리하고 벽돌 내구도는 `damageBrick()`에서 줄입니다. 조준 미리보기도 `moveBall()`을 사용하므로 실제 공과 같은 경로를 따르지만 벽돌 내구도에는 영향을 주지 않습니다.

공의 이동 구간에서 벽과 벽돌에 가장 먼저 닿는 시점을 계산하고, 그 위치에서 반사합니다. 같은 시점에 여러 벽돌에 닿으면 각 벽돌의 내구도를 한 번씩 줄입니다. 기존과 같이 공의 반지름만큼 확장한 사각형을 충돌 범위로 사용합니다.

## index.js 함수 설명

아래는 코드에 등장하는 순서대로 정리한 함수의 역할입니다. `deltaSeconds`는 초 단위의 경과 시간, `timeMs`는 애니메이션 프레임에서 전달받는 밀리초 단위 시각입니다.

### 점수와 턴 진행

| 함수 | 하는 일 |
| --- | --- |
| `loadBestScore()` | 로컬 저장소에서 최고 점수를 숫자로 읽어 반환합니다. 값이 없거나 숫자로 변환되지 않거나 저장소 접근이 실패하면 `0`을 반환합니다. |
| `updateScoreboard()` | 현재 점수와 최고 점수를 화면에 표시합니다. 최고 기록을 경신하면 저장소에도 기록하고, 발사 중일 때만 회수 버튼을 활성화합니다. 저장이 실패해도 실행 중인 게임의 최고 점수는 유지합니다. |
| `addBrickRow()` | 열 순서를 무작위로 섞어 맨 위에 벽돌 3~5개와 빈 열의 공 추가 아이템 1개를 만듭니다. 벽돌 개수·색상은 점수에 따라 정하고, 각 벽돌의 내구도는 현재 점수로 설정합니다. |
| `resetGame()` | 벽돌·아이템·공·파티클과 턴 상태를 초기화합니다. 점수와 공 개수를 1로, 발사 위치를 중앙으로 설정하고 종료 화면을 숨긴 뒤 첫 벽돌 줄과 점수판을 갱신합니다. 최고 점수는 유지합니다. |
| `launchBalls()` | 조준 상태에서 발사 상태로 전환하고 발사 개수, 획득 개수, 발사 경과 시간, 첫 착지 위치를 초기화합니다. 실제 공 생성은 `updateShooting()`이 담당합니다. |
| `finishTurn()` | 획득한 공을 다음 턴의 공 개수에 더하고 첫 착지 위치를 새 발사 위치로 정합니다. 공 목록을 비우고 벽돌·아이템을 한 칸 내리며, 바닥 근처까지 내려온 아이템은 자동 획득합니다. 벽돌이 바닥에 닿으면 종료 화면을 표시하고, 아니면 점수를 1 올려 새 줄을 추가한 뒤 조준 상태로 돌아갑니다. |
| `recallBalls()` | 발사 중인 턴을 즉시 끝냅니다. 첫 착지 위치가 없으면 첫 공의 X좌표 또는 기존 발사 위치를 사용하고 `finishTurn()`을 호출합니다. 아직 발사하지 않은 공도 추가 발사하지 않습니다. |

### 충돌, 공 이동, 효과 갱신

| 함수 | 하는 일 |
| --- | --- |
| `createParticles(x, y, color, particleCount = 9)` | 지정한 위치와 색상으로 파티클을 만듭니다. 각 파티클에는 무작위 속도와 0.5초의 수명을 지정하며, 기본 생성 개수는 9개입니다. |
| `damageBrick(brick)` | 벽돌 내구도를 1 줄이고 0.09초 동안 피격 표시가 나오도록 설정합니다. 내구도가 정확히 0이 되면 파괴 파티클을 생성합니다. 벽돌 목록에서의 제거는 `updateShooting()`에서 처리합니다. |
| `brickContact(ball, brick, dx, dy)` | 공이 이동량 `dx`, `dy`만큼 움직이는 구간에서 벽돌에 진입하는 시점을 계산합니다. 충돌하면 `{ time, reflectX, reflectY, brick }`, 충돌하지 않으면 `null`을 반환합니다. 공이나 벽돌 상태를 직접 변경하지 않습니다. |
| `axisTimes(position, travel, min, max)` | `brickContact()` 내부 함수입니다. 한 축에서 범위에 진입하고 이탈하는 시점을 `[진입, 이탈]`로 반환합니다. 이동량이 0이면 현재 위치가 범위 안쪽에 있을 때 `[-Infinity, Infinity]`, 경계 위나 범위 밖일 때 `null`을 반환합니다. |
| `moveBall(ball, deltaSeconds)` | 왼쪽·오른쪽·위쪽 벽과 살아 있는 벽돌 중 가장 먼저 닿는 위치까지 공을 이동하고 속도의 X축 또는 Y축 부호를 뒤집습니다. 충돌이 없으면 전체 이동량만큼 움직입니다. `{ bounced, bricks }`로 충돌 여부와 접촉한 벽돌 목록을 반환하며 내구도는 변경하지 않습니다. |
| `consider(contact)` | `moveBall()` 내부 함수입니다. 이동 구간 밖의 충돌 후보를 제외하고 가장 이른 충돌을 보관합니다. `CONTACT_EPSILON` 이내의 거의 동시 충돌은 함께 모아 여러 축·벽돌의 접촉을 처리합니다. |
| `createLaunchBall()` | 현재 발사 위치 바로 위에서 조준 방향으로 출발하는 공 객체 `{ x, y, vx, vy }`를 반환합니다. 조준 방향에 `BALL_SPEED`를 곱해 속도를 정하며, 공 목록에 추가하지는 않습니다. 실제 발사와 미리보기가 함께 사용합니다. |
| `collectPickups(ball)` | 공 중심과 아이템 사이의 거리가 `PICKUP_HIT_DISTANCE`보다 작으면 획득 처리합니다. `taken`으로 중복 획득을 막고 `collectedBallCount`를 늘리며 연두색 파티클 12개를 만듭니다. |
| `updateShooting(deltaSeconds)` | `SHOT_INTERVAL`에 맞춰 공을 순차 생성하고, 프레임을 작은 물리 스텝으로 나눠 이동·충돌·벽돌 피해·아이템 획득을 처리합니다. 바닥에 도착한 공은 첫 착지 위치로 모읍니다. 파괴된 벽돌과 획득한 아이템을 제거하고, 모든 공의 발사와 귀환이 끝나면 `finishTurn()`을 호출합니다. |
| `updateEffects(deltaSeconds)` | 파티클을 속도에 따라 이동시키고 수명을 줄여 만료된 파티클을 제거합니다. 벽돌의 피격 표시 시간도 줄입니다. |

`brickContact()`의 `time`은 이번 이동 구간의 비율입니다. `0`은 시작점, `1`은 끝점이며, `0.4`는 이동량의 40% 지점에서 충돌한다는 뜻입니다. X축과 Y축의 진입 시점 중 늦은 값과 이탈 시점 중 빠른 값을 비교해 두 축 모두 범위 안에 있는 구간을 찾습니다. 충돌 범위는 공 반지름만큼 확장한 사각형이므로 모서리에서는 정확한 원과 사각형 충돌의 근사입니다.

`moveBall()`은 충돌 후 남은 시간만큼 추가 이동하지 않습니다. 해당 스텝은 첫 접촉 위치에서 끝나고 다음 물리 스텝에서 반사된 방향으로 움직입니다. 바닥 착지와 귀환은 `updateShooting()`에서 따로 처리합니다.

### 화면 그리기

| 함수 | 하는 일 |
| --- | --- |
| `drawCircle(x, y, radius, color)` | 지정한 위치에 지정한 반지름과 색상의 채워진 원을 그립니다. 공, 아이템, 배경 점 등에 사용합니다. |
| `drawLabel(text, x, y, size, color, weight = 600)` | 글꼴 크기·색상·굵기를 지정하고, 주어진 좌표를 중심으로 텍스트를 그립니다. |
| `drawBackground()` | 게임 영역에 작은 점을 일정 간격으로 배치해 배경 무늬를 그립니다. |
| `drawBricks()` | 벽돌 사각형과 중앙의 남은 내구도를 그립니다. 피격 표시 시간이 남아 있으면 벽돌을 흰색으로 표시합니다. |
| `drawPickups(timeMs)` | 공 추가 아이템의 연두색 원과 `+` 표시를 그립니다. 바깥 테두리의 반지름을 시간에 따라 바꿔 맥동 효과를 냅니다. |
| `drawFloor()` | 공이 귀환하는 바닥선을 점선으로 그립니다. |
| `drawAimPreview()` | 임시 공을 만들고 `moveBall()`로 2px씩 이동시키며 첫 충돌까지 점선 경로를 그립니다. 첫 충돌 위치에는 실제 공 크기의 원을 표시합니다. 벽돌에 피해를 주거나 아이템을 획득하지 않습니다. |
| `drawBalls()` | 조준 중에는 발사 위치의 공과 공 개수를 표시하고, 드래그 중이면 조준 미리보기도 그립니다. 공 목록에 있는 공은 귀환을 마친 공까지 표시하며, 발사 중에는 이번 턴의 공 개수와 추가 획득 개수를 표시합니다. |
| `drawParticles()` | 파티클을 작은 둥근 사각형으로 그립니다. 남은 수명에 비례해 투명도를 낮춰 사라지는 효과를 냅니다. |
| `drawGame(timeMs)` | Canvas를 지운 뒤 배경 → 벽돌 → 아이템 → 바닥 → 공 → 파티클 순서로 전체 화면을 다시 그립니다. |

### 입력과 애니메이션 루프

| 함수 | 하는 일 |
| --- | --- |
| `updateAim(event)` | 포인터의 화면 좌표를 Canvas 내부 좌표로 변환합니다. 발사 위치에서 포인터로 향하는 벡터의 Y성분을 `-35` 이하로 유지하고, 수직 기준 좌우 발사 각도를 `MAX_AIM_ANGLE_DEGREES`(기본 75도)로 제한합니다. 제한한 각도로 길이가 1인 방향 벡터를 만들어 `aimDirection`에 저장합니다. |
| `animateFrame(timeMs)` | 이전 프레임과의 시간 차를 초로 계산하고 `MAX_FRAME_DELTA`로 제한합니다. 발사 중이면 공 상태를 갱신하고, 항상 효과 갱신과 화면 그리기를 수행한 뒤 `requestAnimationFrame()`으로 다음 프레임을 예약합니다. |

이름이 없는 이벤트 콜백과 파일 전체를 감싼 함수도 다음 역할을 합니다.

| 함수 또는 이벤트 | 하는 일 |
| --- | --- |
| 파일 전체의 즉시 실행 함수 `(() => { ... })()` | 게임 변수와 함수를 별도 범위에 두고 DOM 참조와 이벤트를 설정합니다. 마지막에 `resetGame()`으로 게임을 준비하고 첫 애니메이션 프레임을 예약합니다. |
| Canvas `pointerdown` 콜백 | 조준 상태에서 기본 포인터의 주 버튼 입력만 받습니다. 드래그를 시작하고 포인터를 캡처한 뒤 조준 방향을 갱신합니다. |
| Canvas `pointermove` 콜백 | 드래그 중인 기본 포인터의 움직임에 맞춰 조준 방향을 갱신합니다. |
| Canvas `pointerup` 콜백 | 드래그 중인 기본 포인터를 놓으면 마지막 조준 방향을 반영하고 `launchBalls()`를 호출합니다. |
| Canvas `pointercancel` / `lostpointercapture` 콜백 | 입력 취소 또는 포인터 캡처 해제 시 드래그 상태를 해제합니다. |
| 다시 하기 버튼 `playAgain`의 `click` 콜백 | `resetGame()`을 호출해 새 게임을 시작합니다. 재시작 버튼은 `resetGame`, 회수 버튼은 `recallBalls`를 콜백으로 직접 등록합니다. |

`map`, `filter`, `some`, `every` 등에 전달하는 짧은 화살표 함수는 각 함수 안에서 목록 변환, 항목 선택, 조건 검사를 수행하는 보조 콜백입니다.

## 확인

```sh
npm run check
npm test
```

게임 로직 테스트는 가상 Canvas 환경에서 고속 이동, 모서리 반사, 충돌 순서, 여러 벽돌 동시 접촉, 조준 미리보기, 발사, 단계 점수, 최고 기록 저장, 회수, 게임 종료, 재시작, 터치 취소를 검증합니다. 실제 브라우저 렌더링 검증은 별도로 진행해야 합니다.
